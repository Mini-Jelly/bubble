# bubble

一个给 [Typecho](https://typecho.org/) 用的博客主题。轻、干净、明暗自适应，不依赖 jQuery。

> 演示站点：<https://jjj8.top>

**完全不懂 Typecho 也没关系**，照着下面「三分钟装上」做一遍就能跑起来。

---

## 🌮 三分钟装上

### 第 1 步：把主题文件放进网站目录

Typecho 的主题统一放在 `usr/themes/` 下面。你要让最终路径变成这样：

```
你的网站根目录/
└── usr/
    └── themes/
        └── bubble/          ← 主题文件夹，名字就叫 bubble
            ├── index.php
            ├── core/
            ├── views/
            └── ...
```

拿文件的两种方式，**任选一种**：

| 方式 | 适合谁 | 怎么做 |
| --- | --- | --- |
| **下载发行版压缩包**（推荐） | 只想用的 | 解压后得到一个 `bubble/` 文件夹，整个拖进 `usr/themes/` 即可 |
| `git clone` | 要改代码的 | 见下方「二次开发」👉 **克隆下来必须先构建一次，否则页面没有样式** |

### 第 2 步：在后台启用

登录 Typecho 后台 → 左侧菜单 **控制台 → 外观** → 找到 **bubble** → 点 **启用**。

### 第 3 步：看一眼前台

打开网站首页。轮播图里是两张占位图、页脚没有备案号——都是正常的，下一步去配。

---

## ⚠️ 装好之后先做这两件事

1. **去后台「外观 → 设置外观」把主题设置过一遍。** 至少填一下轮播图和备案号，不然首页会顶着两张占位广告图。
2. **确认 `dist/` 目录在。** `dist/` 里是编译好的 CSS / JS / 字体，是**运行时依赖，不是缓存**。
   如果你是自己 `git clone` 下来的，仓库里**没有**这个目录，必须执行：

   ```bash
   npm install
   npm run build
   ```

   > 忘了这一步的典型症状：页面能打开，但**完全没有样式**，一片白底黑字。

## 🎛 后台设置速查

后台 **控制台 → 外观 → 设置外观** 里有 13 个选项，分 5 组。

### Global（全站）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| **主题颜色** | blue | 12 种配色任选。**访客可以在右下角自己换，访客的选择优先于这里** |
| **字体来源** | 系统字体 | `系统字体`＝用访客设备自带字体，不下载任何字体文件；`站点字体`＝用主题内置的 HarmonyOS Sans SC 子集，中文页面会多下载约 460KB |
| **全局新窗口打开** | 关闭 | 开启后站外链接在新标签页打开（站内链接、锚点不受影响） |
| **回到顶部按钮** | 显示 | 滚动超过一屏后，右下角出现回到顶部按钮 |

### Home（首页）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| **轮播图** | 两张占位图 | 一行一张，格式 `图片链接 || 跳转链接 || 跳转文字`。图片建议 **947 × 250 px** |
| **标签云** | 开启 | 首页底部显示标签云 |
| **置顶文章** | 空 | 填文章 cid，多个用 `||` 隔开，例如 `1 || 2 || 3`。cid 就在文章编辑页的网址里（`/archives/86/` 里的 86 就是） |

### Article（文章页）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| **文章目录** | 开启 | 文章页右上角浮出目录，可拖动、可缩放 |

### Other（其它）

| 选项 | 说明 |
| --- | --- |
| **ICP 备案号** | 填在页脚，例如 `京ICP备00000000号-1` |
| **自定义头部代码** | 塞统计代码用的（Google Analytics、百度统计等），输出在 `</head>` 前 |
| **自定义底部代码** | 输出在 `</body>` 前，某些插件需要 |

### Dev（调试，线上请都关掉）

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| **近期更新文章** | 关闭 | 开启后导航栏出现入口。⚠️ 还需要在后台**新建一个独立页面**，缩略名填 `recent-modified`，自定义模板选「最近修改的文章」，否则点了会 404 |
| **显示页面耗时** | 关闭 | 页脚输出页面生成耗时与内存占用，仅调试用 |

## 🎨 访客自己能调什么

右下角有一个悬浮按钮组：**个性化设置** + **回到顶部**。

点开齿轮，访客可以自己改四样东西——**外观**（跟随系统 / 亮 / 暗）、**正文字号**（滑条 4 档）、**字体来源**（系统 / 站点）、**主题色**（12 色）。

规则很简单：

- 访客**没动过**的项 → 用你在后台设的默认值；
- 访客**动过**的项 → 存在他自己浏览器的 localStorage 里，**优先级高于后台设置**，刷新、换页都还在；
- 点「恢复默认」→ 清掉本机的所有改动，重新跟随你的后台设置。

也就是说：**你后台改配色，对所有没自己改过的访客立刻生效。** 不用担心改不动。

## 🩺 常见问题

**Q：启用主题后页面完全没有样式，白底黑字。**
`dist/` 目录丢了。发行版压缩包里自带，`git clone` 下来的没有——跑一次 `npm install && npm run build` 就有了。

**Q：我改了 SCSS 或 JS，刷新页面却没变化。**
浏览器里跑的是 `dist/` 里的编译产物，改 `src/` 不会自动生效，要重新 `npm run build`。
如果构建完还没变，八成是浏览器缓存——主题已经给所有静态资源加了版本查询串（`?v=版本号.文件时间`），正常不会命中旧文件；实在不行 Ctrl+F5 强制刷新。

**Q：首页能看，但一分页 / 一进二级目录，图片全裂了。**
后台设置里填了**相对路径**（例如 `usr/themes/bubble/a.png`，开头没有 `/`）。浏览器会按当前页面目录去拼，二级页面自然找不到。**填完整网址**（`https://你的域名/...`）最稳妥。

**Q：评论提交后老是跳回原页面，发不出去。**
先确认站点后台没开什么奇怪的反垃圾插件。本主题已经正确调用 Typecho 的 `header()`，`评论提交失败` 在纯净的 Typecho 1.2.x 上不会出现。

**Q：怎么换成自己的 Logo？**
替换 `assets/img/logo/logo.png`。favicon 是 `assets/img/favicon/favicon.svg`。

**Q：想关掉右下角的悬浮按钮组？**
后台 Global 组里把「回到顶部按钮」设为隐藏即可（个性化设置面板跟着一起隐藏）。

## 🐒 二次开发

### 环境要求

- Node.js **18+**（开发时用的是 22）
- npm
- PHP **7.4+**（主题在 Typecho 1.2.1 / PHP 7.4 上验证）

### 上手

```bash
git clone https://github.com/Mini-Jelly/bubble.git
cd bubble

npm install        # 装依赖
npm run dev        # 起开发服务器，改 src/ 自动热更新
npm run build      # 生产构建，输出到 dist/
```

> **`npm run dev` 和 `npm run build` 只改 `dist/`，不碰 PHP。**
> 改 PHP 模板直接刷新页面就行，不用重启任何东西。

### 改哪里

| 想改什么 | 去哪 |
| --- | --- |
| 页面 HTML 结构 | `views/`（导航、页脚、文章卡片、评论区…） |
| 页面样式 | `src/scss/views/`（与 `views/` 一一同名） |
| 全局样式 / 颜色变量 / 栅格 | `src/scss/` 顶层 |
| 交互脚本 | `src/js/main/` |
| 后台设置项 | `core/config.php` |
| 公共函数 | `core/func.php` |

**视图和样式是「同名一对」**：`views/nav.php` ↔ `src/scss/views/_nav.scss`，找起来不用猜。

配色改 `src/scss/_color.scss` 里的两个 mixin（`palette-light` / `palette-dark`），
⚠️ **新增颜色变量必须亮暗两套都定义**——`var()` 取不到值时整条 CSS 声明会静默失效，
不报错、不警告，只是颜色悄悄变回继承色。

### 打包发布

```bash
npm run build && npm run package
# → .package/bubble-<版本号>.zip
```

压缩包顶层就是 `bubble/`，用户解压到 `usr/themes/` 即可覆盖安装。

打包用的是**白名单**（见 `scripts/package.js`）：只有 Typecho 运行时真正会读的文件才进包，
`src/`、`webpack/`、`scripts/`、`docs/` 和所有配置文件都不会跟出去。

### 🔖 版本与发布

版本号遵循[语义化版本](https://semver.org/lang/zh-CN/)，**唯一真源是 `package.json` 的 `version`**。
主题头 `index.php` 里的 `@version` 由脚本自动同步，`@build` 记录构建日期 —— 这两个字段都不要手改。

| 命令 | 用途 |
| --- | --- |
| `npm run version:sync` | 只把 `package.json` 的版本同步到 `index.php` |
| `npm run release:patch` | 修订号 +1：向下兼容的问题修复 |
| `npm run release:minor` | 次版本号 +1：向下兼容的功能新增 |
| `npm run release:major` | 主版本号 +1：不兼容的改动 |

`release:*` 会依次完成：升版本号 → 同步 `index.php` → 提交 → 打 `vX.Y.Z` 标签。
推送标签即可在 GitHub 上形成发布点：

```bash
git push && git push --tags
```

发版前请把变更写入 [CHANGELOG.md](./CHANGELOG.md)。

提交信息遵循 [Conventional Commits](https://www.conventionalcommits.org/zh-hans/)，
常用前缀：`feat` 新增、`fix` 修复、`perf` 性能、`refactor` 重构、`docs` 文档、`chore` 杂项。
**一个功能一个提交**，同一功能的代码与文档放在同一个提交里，方便对着看。

### ✏ 开发规范（仅适用于本项目）

- 所有文件名用 snake_case（`post_meta.php`、`_tag_cloud.scss`）
- CSS 类名、JS 的 id 用短横线连接（`.article-card`、`#backToTop`）
- PHP 函数名、JS 函数名用小驼峰（`getArticleCardMedia()`、`syncAll()`）
- z-index 不写字面量，统一用 `:root` 里的 `--z-*` 令牌

## 💼 目录结构

一张表看懂每个文件夹装的是什么、什么时候被用到：**[docs/STRUCTURE.md](./docs/STRUCTURE.md)**

最短版：

```
根层 *.php   Typecho 路由入口（文件名由框架规定，不能挪）
core/        服务端逻辑：公共函数 / 后台设置表单
views/       服务端视图片段，由 need() 包含
assets/      不经构建的图片，PHP 直接引用
src/         构建源码（scss / js / fonts），要经过 webpack
dist/        构建产物，被 git 忽略但运行时依赖
scripts/     工程脚本（版本同步 / 打包）
docs/        设计说明与历史审查台账（进仓库，不进发布包）
```
